# Go implementation

**Version:** 2.2.0
**Default run mode:** `SNYK_CLI`

This directory contains the standalone Go implementation of the Snyk SBOM →
ServiceNow utility. It compiles to a static executable with no Python, Go
toolchain, or package dependency on the target host.

See the repository-root [`README.md`](../README.md) for the complete
configuration, Jenkins, and customer deployment documentation.

## Build and verify

Go 1.22 or newer is required to build:

```bash
cd go
make check
make build
./bin/snyk-sbom-to-servicenow --version
```

Build Linux, macOS, and Windows release binaries for amd64/arm64:

```bash
make cross-compile VERSION=2.2.0
```

Artifacts are written to `go/dist/`.

## Run

The binary loads `.env` from the current working directory. `SNYK_CLI` is the
default, so an SBOM file path is required unless API mode is selected explicitly.

```bash
# Default: upload a file generated by the native Snyk CLI
./bin/snyk-sbom-to-servicenow --sbom-file-path ./sbom.json

# Snyk REST API mode
RUN_MODE=SNYK_API ./bin/snyk-sbom-to-servicenow

# Optional ServiceNow build ID from the environment
RUN_MODE=SNYK_API BUILD_ID='release 2026.10.13' \
  ./bin/snyk-sbom-to-servicenow

# A command-line build ID overrides BUILD_ID
BUILD_ID='environment-build' \
  ./bin/snyk-sbom-to-servicenow --sbom-file-path ./sbom.json \
  --buildid='command-build'
```

`BUILD_ID` is optional. If `--buildid` is present, it takes precedence even
when explicitly empty; use `--buildid=` to suppress an environment value.
When the effective value is empty, the upload omits `buildId`. Spaces and
special characters are URL encoded automatically.

## ServiceNow authentication

`SNOW_AUTH_METHOD` accepts `BEARER` (the backward-compatible default) or
`BASIC`, case-insensitively. Configure one credential set in `.env`:

```dotenv
# Bearer
SNOW_AUTH_METHOD=BEARER
SNOW_ACCESS_TOKEN=your-access-token

# Or Basic
SNOW_AUTH_METHOD=BASIC
SNOW_USERNAME=your-service-account
SNOW_PASSWORD=your-service-account-password
```

Only the selected method's credentials are required. Invalid methods and
missing selected credentials fail before network activity; ServiceNow 401/403
responses identify the relevant variable names without exposing values.

Basic authentication is Base64 encoding, not encryption. Keep
`SSL_VERIFY=true`; configure `CA_BUNDLE` when a private CA is required. See the
root README for complete migration, Jenkins, and troubleshooting guidance.

Use `--version` for the embedded semantic version and `--help` for flags.

## Source layout

```text
cmd/snyk-sbom-to-servicenow/  executable entrypoint
internal/apperr/              typed errors and exit codes
internal/climode/             SNYK_CLI orchestration
internal/config/              .env loading, defaults, validation
internal/httpx/               HTTP/TLS wrapper
internal/logging/             leveled logging
internal/redact/              secret redaction
internal/sbomfile/            timestamped file persistence
internal/scope/               API scope orchestration and summary
internal/servicenow/          ServiceNow upload client
internal/snyk/                Snyk SBOM and discovery clients
```
